# GitHub inbox

`dsh-inbox-bridge` 是一个 DSH 插件。它不替你看 GitHub 账号上的消息，它盯的是**这个会话在 GitHub 上做的事有没有回音**：我提的 PR 被评审了吗、CI 挂在哪一次、派给我的 issue 有人回了没有。查到的东西汇总成一条消息，在回合边界注入会话上下文——必要时也能主动开一轮。它只读 GitHub，不动你的仓库。

## 为什么需要它

用 agent 写代码，仓库里的工作并不跟着对话走。CI 要跑几分钟到几十分钟，失败发生时 agent 正在别处；PR 等人评审、issue 等人回应，也没人接手。等想起来去翻，往往已经过了最该修的时候。

把它装进会话，等于给每个会话配一个自己的通知器：它按这个会话的身份和归属去查，谁做的事的回音就送到谁那里。开发本身和仓库维护不再互相打断。

它只读的原因也在这里：它负责让 agent 知道该做什么，动手的是你眼前的那一轮。

## 它做什么

- **按身份判断相关性。** 用本机 `gh` 的登录身份（或配置的 App 身份）查询仓库，只保留以你为作者、评审人、指派对象或提及对象的事件。
- **我维护的仓库里出现的东西也算我的。** 仓库对我是 owner 或 admin 时，别人开进来的 PR 与 issue 就是我要做的决定，不必等我被指派或 @；不是 owner/admin 的仓库不算。
- **自己的工作跟人走。** 除了接管的仓库，它还用搜索接口在整个账号能读到的范围里找你自己的条目：你在别的仓库开的 PR、派给你的 issue、提到你的评论，同样会回来找你。
- **接管一个仓库。** 打开工作区时第一个会话自动接管它所在的仓库，之后的会话默认不接管；面板里可以手动加减。接管者收到整个仓库的信号（默认分支 CI、安全告警、发布）。
- **两级归属。** 仓库级的事只给接管者；条目级的事（某个 PR / issue 上的检查、评审、指派、@）给在那个仓库里干活的会话。一条事实只叫一个会话。
- **轮询跟随回合。** 会话开始一次、进行中每 1 分钟一次、结束一次；`wakeup` 下空闲也按同一间隔取数，否则没法在你不在时叫你。
- **顺手清理。** 读过的线程在读收件箱的那条 `gh` 调用里就标成已读，下次不再重复报给你。没有浏览器、不用登录；需要令牌的 `notifications` 权限，`doctor` 会直说有没有。
- **面板可改。** 状态行胶囊在有未处理事件时显示蓝点与数量；悬停展开事件列表与两组开关：提醒方式、节奏（空闲多久、每小时几次），外加拿管仓库的清单（粘贴仓库链接或写 `owner/name`）。

## 安装

在 DSH 的「插件 → 发现」里添加索引源：

```text
https://c3115644151.github.io/dsh-inbox-bridge/index.json
```

或者从源码：

```powershell
git clone https://github.com/c3115644151/dsh-inbox-bridge
dsh plugin add ./dsh-inbox-bridge
```

安装后在插件配置里指定工作目录 `cwd`；仓库与身份从该目录的 `git remote` 与 `gh` 读取。

## 边界

- 只读：不合并、不评论、不修改仓库。
- 默认不主动开启对话；只有 `delivery: wakeup` 命中 `wakeOn`、这条事实归属这个会话、会话足够空闲、两个预算都还有余额时才会，任何一道门不过就退回只排队。
- 它保证一条事实只叫一个会话，但两个已经动手的 agent 之间它管不了。
- GitHub 网页上的「Done」没有公开接口，所以插件不追求那个状态：对轮询器来说已读与 Done 等价——两者都不再出现在未读流里。
- 状态保存在本机 `<cwd>/.work/` 下，不跨机器同步。
