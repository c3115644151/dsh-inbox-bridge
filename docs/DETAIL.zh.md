# GitHub inbox

`dsh-inbox-bridge` 是一个 DSH 插件。每个会话订阅自己的 GitHub 仓库；插件按身份判断其中哪些事件与你有关，汇总成一条消息，在回合边界注入会话上下文。它只读 GitHub，不代替你操作，也不会主动开启一轮对话。

## 为什么需要它

用 agent 写代码，仓库里的工作并不跟着对话走。CI 要跑几分钟到几十分钟，失败发生时 agent 正在别处；PR 等人评审、issue 等人回应，也没人接手。等想起来去翻，往往已经过了最该修的时候。

把它装进会话，等于让 agent 像维护者一样盯着仓库：每轮取一次数，CI 挂了就修，有人请你评审就审，指派给你的 issue 就接。开发本身和仓库维护不再互相打断。

它只读的原因也在这里：它负责让 agent 知道该做什么，动手的是你眼前的那一轮。

## 它做什么

- **按身份判断相关性。** 用本机 `gh` 的登录身份（或配置的 App 身份）查询仓库，只保留以你为作者、评审人、指派对象或提及对象的事件。
- **只看仓库，不看通知箱。** 通知箱按账号推送，分不清会话与仓库；这里直接查仓库状态，同一账号下两个仓库互不干扰。
- **轮询跟随回合。** 会话开始一次、进行中每 1 分钟一次、结束一次；空闲不发请求。
- **面板可改。** 状态行胶囊在有未处理事件时显示蓝点与数量；悬停展开事件列表与三组开关：提醒方式、消息清理（关闭 / 已读 / 归档，一档三态）、订阅哪些仓库（粘贴仓库链接或写 `owner/name`）。

## 安装

在 DSH 的「插件 → 发现」里添加索引源：

```text
https://c3115644151.github.io/dsh-inbox-bridge/index.json
```

或者从源码：

```powershell
git clone https://github.com/c3115644151/dsh-inbox-bridge
dsh plugin add ./dsh-inbox-bridge
```

安装后在插件配置里指定工作目录 `cwd`；仓库与身份从该目录的 `git remote` 与 `gh` 读取。

## 边界

- 只读：不合并、不评论、不修改仓库。
- 默认不主动开启对话；只有 `delivery: wakeup` 且命中 `wakeOn` 时才会。
- 归档到 Done 依赖一次浏览器登录（GitHub 没有归档 API）。
- 状态保存在本机 `<cwd>/.work/` 下，不跨机器同步。
